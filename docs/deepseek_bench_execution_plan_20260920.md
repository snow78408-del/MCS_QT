## 2. P0：实体实验前必须补强的采集器

现有 `tools/plant_flow_transient_capture.py` 不应直接用于本轮正式采集。2026-09-20 静态检查发现：

1. `TransientTracker` 用给定 `1/rate` 和计数推算时间；`run_live()` 没有保存逐帧时间戳、帧号及完整原始片段。
2. 循环在发出启动指令后才读帧，缺少持续记录的指令前基线。
3. `started=True` 只在启动回读成功后设置。若泵已收到启动命令但回读失败，`finally` 可能跳过停泵。必须处理“可能已经启动”的状态。
4. 相机参数设置失败只写警告后继续；无有效帧时可能持续等到整段超时。
5. 未具备独立的真实速度分支证据，却可把推测值按默认标尺转换为 mm/s 并报告稳定。
6. 停泵发生在硬件互斥锁作用域外；停机验证失败也不能只记录日志后作为成功结束。

请复用现有适配器和 `PumpHardwareService`，补齐后才生成最终硬件运行命令。优先提供显式离线/现场模式，默认离线；本文不声称这些模式已经实现。不要修改 GUI 页面使其直接调用底层硬件。

实现要求：

- 先开始有时间戳的连续采集，再记录命令提议、发出、回读和实际开始/结束事件；每个事件关联 command_id 与单调时钟。
- `FrameData` 已有 `frame_id`、`host_monotonic_timestamp`、`hardware_frame_id`、`hardware_timestamp_ticks`、`sdk_host_timestamp_ticks`、`lost_packet_count`、`exposure_time_us`。检查实际 adapter 是否填充；字段默认 0 不代表测得有效值，不支持的硬件字段记录 null 和原因，不臆造设备时钟频率。
- 保存原始帧或保持原时间采样的通道裁剪、裁剪变换和独立帧索引。先评估写盘吞吐；处理/存储跟不上时显式记录丢帧并中止受影响试验，不能用无界队列隐藏问题。
- 对设置写入、回读、帧超时、磁盘写入、取消和异常给出有界处理。泵命令发出前即进入“可能运行”保护状态，在仍持有设备独占锁时停泵并验证。
- 停泵回读失败时按计划有限重试；仍失败则标为 STOP_UNVERIFIED，立即要求操作者现场确认停止，不发布成功结论，不自动重启。
- 速度分析采用明确混叠状态；未解分支不填真实速度或 Hz；缺少标尺不填 µm。可继续保存像素诊断，但不能授权控制。

测试至少覆盖：启动已发出但回读失败、第二路写入失败、无帧、重复/丢帧、非单调时间戳、写盘失败、Ctrl+C/取消、停机验证失败、正常完成。全部用 mock；涉及生命周期、控制或线程时运行完整 pytest。保留测试日志和最终脚本哈希。

## 3. P1：接管、标尺和尺寸测量

操作者追溯储液容器 → 注射器 → 泵通道 → 芯片入口 → 观测段 → 收集端，拍照并填写映射。不得根据 70:20、亮度占空比或“对调后变大/变小”确定相别。

保持与实验相同的光学配置，用独立标尺拍摄至少三处可读间隔，保存原图和端点坐标，报告 µm/px 的离散性及来源。通道深度必须对应当前芯片；若未确认，三维体积结论保持未知，不影响先做像素域回放。

选用现有 12 张样本做标注练习，再对新采集的清晰帧标注管壁及成对弯月面坐标，给出边界不确定区间。先看无检测叠加的图，再打开算法候选，避免把算法输出当人工真值。难辨的帧标为不可标注并保留，不删除。

产出 `apparatus.json`、`scale_measurements.json`、`annotations.json` 及原图。几何标定与泵动力学标定分别记录。

## 4. P2：独立输送量核对

先核对型号与代码表，不因为旧的“16 倍”推断改代码。分别测两路；接入芯片与脱离芯片的测量明确区分负载条件。芯片接通时单开一路可能改变相态和流路，因此不能把这种操作默认当作与双路工况等价。

每路在已确认基线命令附近做至少 3 次独立收集。具体命令、收集时长和累计量由运行表给出；根据仪器分辨率及可用行程选择，不照抄旧的 3 分钟或 1000 µL。

记录空容器/收集后读数、时间区间、液体密度及来源、配置、预运行状态、背景变化、剩余液量、异常。计算：

`Q_actual = mass_change / density / elapsed_minutes`

质量单位为 g、密度为 g/mL 时，结果乘 1000 得 µL/min。每路分别求 `r_i=Q_actual_i/Q_cmd_i` 及不确定度。推杆法必须使用实际内径依据，仅证明推杆排量，不能单独排除系统内滞留、泄漏或压缩。

若发现差异，报告并核对原因，不立即按倒数倍率调流。需要改配置时先停止、记录变更、重新测量，前后数据分组。

## 5. P3：相机与时间链试采

先在确认的工况下采一个受时长/容量限制的短片，验证帧号、时间戳、曝光回读、记录文件可读和图像边界清晰度。先完成此阶段，再安排完整响应。

如比较两种采样率，记录实际采样时间且尽量保持同一稳定工况；通过多组独立证据约束速度分支。多帧跨度相关性一致、知道流向或改帧率后数值接近，均不单独等同于解除混叠。不能唯一选分支就继续报告 `ALIAS_UNRESOLVED`。

原图质量、时间信息或写盘不达要求时，先修复采集，不开展长扫描。现有资料不支持一个适用于所有工况的固定 400 fps 门槛。

## 6. P4：最小完整响应，不直接跑大网格

先把已确认工作点写作 `A=(Q1_0,Q2_0)`。为每路提出一个小幅度 `ΔQ_i`，同时检查上下限、命令分辨率、剩余量和最大步长；5% 可作为待确认的初始设计候选，不是自动允许的数值，基线为零时不能用百分比生成阶跃。

先做一路、一个完整往返试采：

1. 连续记录 A 的变化前基线，确认质量指标满足会话计划。
2. 仅改变 Q1 到 `Q1_0+ΔQ1`，Q2 不变；持续记录直到满足预先登记的稳定判据或达到时长/容量上限。
3. 返回 A，记录恢复过程。达到上限仍不稳定时，将该段标为未稳定，本轮停止或按已确认的结束步骤收尾，不自行延长。
4. 检查记录完整性和可辨识性，通过后才按运行表继续负向与重复。

完整最小序列为每路 `A → B+ → A → B− → A`，每个方向计划 3 次重复；测另一路时固定第一路。具体执行表列出每一步命令、最小观察窗口、最大时长、累计量上限和结束条件。若容量不足，分会话完成并重新建立基线，不能默认为自动补液。

稳定判据应由先导数据噪声与实验容差确定，记录窗口长度、斜率/波动限制、持续时间及质量占比。不要用“等够 35 秒”或“必须 10 分钟”替代观测，也不要把半窗变化很小当作整个系统稳定的证明。

P4 首个往返未通过时，不扩展交叉点或二维网格。相机边界不可信时优先做测量修复，不用调泵去迎合算法。

## 7. 停止条件及失败记录

出现以下任一条件，停止当前试验并走已测试的停机/回读路径：

- 操作者取消、可见泄漏/气泡异常/流路脱开、行程或液量到界。
- 命令回读失败或超出允许范围；相机长时间无有效帧、时间链不可用。
- 磁盘容量不足、写入失败、处理积压超限，无法保证完整记录。
- 达到最大单段/总时长、累计输送上限。

停止后保留原始文件、已完成步数、最后命令、错误原因、停泵请求与回读，不删除失败试验，不只汇报成功样本。设备无法确认停止时，优先提示现场人员处置，禁止继续下一步。
