# BO + 扰动预测 + PID + 前馈控制链

## 控制权设计

泵只有一个写入口，控制权由 orchestrator 的状态机独占分配：

1. `OPTIMIZING`：只有 BO 可以下发 Q1/Q2；PID 和前馈不执行。
2. `STABILIZING`：保持 BO 找到的最优 Q1/Q2，不产生新调节量。
3. `RUNNING`：BO 不再写泵；PID 控制器在内部计算 `u_pid + u_ff`，经过同一套限幅、变化率限制、Q1/Q2 相位约束和总流量约束后，只生成一条泵命令。

因此 BO、PID、前馈不会作为三个并行写入者竞争同一执行量。快照中的 `control_owner` 可取 `BO`、`HOLD`、`PID` 或 `PID+FEEDFORWARD`；`requested_output`、`realized_output` 和 `actuator_saturated` 用于审计分配与饱和情况。

## 启动 BO

完成配置、视频准备、系统初始化和实验前检查后，在运行监控页点击“BO寻优”。必须提供：

- Q1/Q2 的实验安全边界；
- 通过实际阶跃实验测得的“泵命令到液滴响应”延迟；
- 延迟测量的不确定度或保守安全余量；
- 不短于“延迟 + 不确定度”的候选点稳定时间；
- 可追溯的延迟测量来源。

串口应答或参数回读耗时不是物理响应延迟，配置会拒绝 `serial_reply`、`device_readback`、`unmeasured` 等来源。代码调用方式：

```python
from backend.orchestrator import BayesianOptimizationConfig

orchestrator.start_optimization(
    BayesianOptimizationConfig(
        target_diameter_um=60.0,
        q1_min=40.0,
        q1_max=60.0,
        q2_min=10.0,
        q2_max=25.0,
        measured_response_delay_ms=1200.0,
        response_delay_uncertainty_ms=200.0,
        settling_time_ms=2000.0,
        response_delay_source="step experiment 2026-08-27",
    )
)
```

BO 首先测量当前已经过泵回读验证的 Q1/Q2 工作点，再使用安全可行域内的 Latin hypercube 初始点和 Matérn 5/2 高斯过程期望改进。每个候选点默认连续采集 3 个完整控制周期，用中位数汇总直径、频率、CV 和实际回读流量；任一周期液滴数不足会清空该候选点的窗口并重试。目标直径采用容差带损失，并可同时加入频率目标、CV、无效液滴比例和移动代价。

“目标函数最低点”和“满足目标的可行点”分别记录。独立确认只会重复同一个满足目标的点，不会误把 CV 较低但直径不达标的点确认成结果。视觉质量持续失败、候选超时或泵回读不一致会安全停止；达到最大有效观测数但未找到目标时，系统保持已观测到的最佳安全点并要求操作员审阅。操作员可以停止后重新设置 BO，也可以通过 `accept_unconfirmed_optimization_best()` 明确接受该点；系统不会自动把未确认点交给 PID。

## BO 到 PID 的切换

BO 成功后先进入 `STABILIZING`，继续保持最优点并等待一个稳定时间和有效视觉窗口。随后调用 `set_operating_point(q1, q2)`：清空 PID 积分、微分历史和前馈历史，并把最优 Q1/Q2 设为新的输出偏置，实现无突跳接管。

PID 的最终命令由一个分配器产生。BO 切换完成后，PID 只拥有以工作点为中心的局部微调区间，默认半径为各泵全局安全跨度的 20%，不会再次充当全局搜索器。若执行器边界、局部权限、Q1/Q2 最小相差、总流量或单周期变化量导致命令不能完全实现，积分会冻结或按实际输出回算，防止 windup。

漂移监督器连续检查直径误差、积分占比和局部分配饱和。连续 5 个有效周期显示局部权限不足时，只在快照中给出 `reoptimization_recommended`，不会在运行中擅自把控制权切回 BO。

## 前馈启用条件

扰动模块默认处于 `COLLECT_ONLY`，不默认授权低权重或完整前馈；但数据量满足要求后会由后台线程训练候选模型。`COLLECT_ONLY` 表示没有扰动模型拥有泵控制权，而不是停止学习。真正作用于泵还必须同时满足：

- 模型 ready、valid、置信度和时效通过；
- 至少完成 20 次影子验证，变化方向与误差门槛通过；
- 当前泵、芯片、流体和注射器组合存在版本化动力学标定，其中包括实测响应延迟及不确定度、控制方向、分配增益、直径灵敏度和安全流量区间；
- 泵物理响应延迟、真实提前信号和预测时域全部满足因果性检查。

通过 `set_disturbance_context()` 提供当前事件的提前信号：

```python
orchestrator.set_disturbance_context(
    disturbance_name="scheduled pressure pulse",
    leading_signal_available=True,
    signal_lead_time_ms=1800.0,
    leading_signal_name="upstream pressure trigger",
)
```

提前量从信号登记时刻开始递减，耗尽后信号自动失效。模型只预测“观测变化减去基线正常动力学”的扰动残差，不再直接生成泵指令，也不能绕过标定或提前信号门。前馈命令统一由已标定的直径灵敏度换算，并受部署阶段权重、变化率和 `feedforward_max_output_fraction` 共同限制。没有可提前观测的外生信号时，系统退化为 BO 工作点加 PID 反馈，前馈保持为零。

新版动力学标定 JSON 使用 `schema_version: 3`。除装置、芯片、泵和注射器身份外，还结构化保存连续相油型号、表面活性剂名称/浓度/计量方式、水相组成和温度。记录包含 Q1/Q2 独立延迟、组合响应延迟、FOPDT 时间常数及不确定度、模型拟合误差、独立验证误差和 `validated_for_pi` / `validated_for_mpc` 分级授权。旧 v1/v2 文件仍可读取用于审计，但不能授权新版实时闭环。

## 运行监控页自动动力学标定

“运行监控”页在实时视频旁提供非模态泵-芯片自动标定窗口；本次实时相机测试取帧和像素/管道标定配置完成，并且操作员在泵页面点击“写入 Q1/Q2 并回读校验”成功后即可开始，不要求人工进入“系统初始化”页。点击开始后，窗口在后台依次执行 `configure()`、`prepare_video()` 和 `initialize_system()`，建立视觉采集、泵通信及安全停机环境，再进入标定；这些安全准备不会被省略。仅执行泵参数读取不能取得标定资格，串口参数或 Q1/Q2 修改后也必须重新写入回读。标定窗口不会阻塞监控页视频刷新，并默认靠监控窗口右侧显示。操作员在同一窗口填写装置、芯片、流体、泵和注射器身份，确认围绕已验证流量使用的 Q1/Q2 小阶跃幅值，并持续查看当前阶跃、有效液滴数、完成数、状态和失败原因。窗口同时提供“暂停并中止”和“停止标定”；暂停会安全停泵并废弃本次未完成结果，不支持从半个阶跃继续。标定拥有独立的 `CALIBRATING` 状态和唯一泵写入权限，PID、BO 与前馈均不参与。

每轮先分别执行 Q1、Q2 正负阶跃，使用生成区塞长体积换算得到的等效直径和泵参数回读，识别无量纲灵敏度 `g_j = d(ln d)/d(ln Q_j)`；然后沿识别方向执行联合正负阶跃。时间常数不再由单个 63.2% 阈值液滴决定，而是使用全部联合阶跃曲线鲁棒拟合共享的一阶惯性纯滞后（FOPDT）模型。建模阶跃结束后，再以不同幅值执行未参与拟合的正负验证阶跃；验证 MAE/NRMSE 未通过时，记录可以保存审计，但不会获得 PI 或 MPC 授权。PID 使用 `g/(g^Tg+lambda)` 分配 Q1/Q2，旧的固定方向和 2:1 倍率不再参与正式闭环。实验不按固定秒数或重复视频帧推进：每次恢复同一基准后，至少累计 30 个全新有效过线液滴并确认稳定；达到 30 滴仍不稳定时继续观察。稳定但低于视觉阈值的通道登记为合法弱通道并退出分配；显著响应方向不一致仍判定标定失败。只有通过独立验证的 schema v3 生成区标定才能授权实时 PI。

任一目标越过 Q1/Q2 边界、总流量、相位最小差值，或发生泵回读不一致、暂停、停止和生命周期令牌失效时，实验立即终止并进入安全停泵路径。实验本身没有固定时长上限；只有连续长时间没有任何新的有效过线液滴时，视觉失联安全看门狗才会终止并停泵，防止传感器失效后真实泵无限无人值守运行。成功完成后也先恢复基准点并验证停泵，不自动应用新标定，更不会打开前馈授权。

用户选择保存位置后生成两个文件：所选 `*.json` 只包含可由基础参数页直接加载的 `PlantCalibrationRecord`；同目录的 `*.measurements.json` 保存实验配置、全部阶跃摘要和逐帧原始测量，以便复核和追溯。新标定写入前端设置，但在下一次重新初始化配置时才生效。

## 在线候选模型生命周期

在线训练不会直接替换活动模型。每累计 `model_update_interval` 个新样本，后台训练器使用最近训练窗口完成分组训练、验证和独立测试；通过者只登记为 `candidate_model`：

运行监控页的“标记扰动阶段”用于在不中断控制的情况下标注 `baseline`、`disturbed` 和 `recovery`。阶段切换会保留当前自动生成的实验 ID 和芯片 ID；基线阶段的幅度固定为零。没有正确阶段标签的数据仍会保存，但通常无法通过扰动事件和基线样本训练门槛。

1. 活动模型继续提供当前预测，候选模型针对同一时刻并行预测；没有活动模型时，候选结果仅用于显示和评分，前馈权重强制为零。
2. 未来观测到达后，系统分别计算候选模型和活动模型的扰动残差误差，比较使用完全相同的实验窗口。
3. 候选模型必须达到最少影子比较数、绝对误差、残差误差和方向准确率阈值；已有活动模型时，候选残差 MAE 还必须默认改善至少 5%。
4. 所有门槛通过后只产生 `candidate_promotion_ready` 提示，不自动晋级。操作员须在初始化、暂停或停止状态点击“晋级候选模型”。
5. 晋级只替换活动预测模型，不修改低权重或完整前馈授权；候选也可以由操作员直接丢弃。

活动模型预测异常时保留既有回滚和安全降级路径；候选训练失败只记录候选错误，不会把仍正常的活动模型标为降级。

## 实时控制周期

实时控制周期由用户填写，允许范围为 7500–30000 ms；7500 ms 只是当前泵在 1200 波特率下完成双通道写入和回读所需约 6 秒后的安全下限，不是固定周期。系统保留用户填写的准确数值，低于下限时明确拒绝配置，不会静默改写成 7500 ms。视觉统计窗口、PID 调度和界面配置使用该周期；硬件事务超时会跳过过期槽位，不会连续补跑。

## 现场使用建议

先完成响应延迟、控制方向和直径灵敏度辨识，再做 BO。扰动数据持续采集并可在线训练候选模型，但本版本不把历史记录导入 BO。低权重前馈需要候选晋级、影子验证和操作员显式授权；完整前馈默认保持未授权。暂停或停止会立即使运行令牌失效；任何正在途中的泵命令都不能跨生命周期继续生效。
