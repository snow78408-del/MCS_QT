# 安全闭环与测量验证规范

## 1. 安全原则

泵的安全许可由 `SafetySupervisor` 管理，独立于 Qt UI 和普通控制线程。每次开始运行生成新的 `session_id + generation`；视觉帧、识别周期和控制命令都必须属于该运行代次。暂停、停止、急停、控制线程异常或心跳超时会先使代次失效，再尝试停泵。停泵未回读确认时，系统只能进入锁存故障，不能显示为已停止。

泵命令发送前需要同时满足：

- 安全状态为 `ARMED`，运行令牌仍有效；
- 编排器状态为 `RUNNING`，暂停和停止事件均未置位；
- 识别结果的 `session_id`、`run_generation` 和 `control_period_id` 有效且未重复；
- 识别数据新鲜，像素比例具有可追溯标定来源；
- Q1/Q2、单位和设备地址通过有限值及范围检查。

双通道更新视为一个安全事务。任一通道写入或回读失败后，控制器停止两通道，尝试恢复已修改参数，再次确认两通道停止；不会自动恢复泵送。

## 2. 操作矩阵

| 当前状态 | 允许操作 | 结果/约束 |
| --- | --- | --- |
| IDLE / CONFIGURED | 配置、准备视频 | 不启动泵 |
| VIDEO_READY / CONFIGURED / STOPPED | 初始化 | 串口探测、参数写入与回读，不启动闭环 |
| INITIALIZED / STOPPED | 开始 | 新建会话和代次，显式启动泵并建立安全心跳 |
| RUNNING | 暂停、停止、急停 | 先废止令牌；暂停也必须确认停泵 |
| PAUSED | 解除暂停、停止、急停 | 解除暂停只回到 INITIALIZED；必须再次点击开始，绝不自动泵送 |
| ERROR | 停止、复位安全锁存、重新初始化 | 只有确认泵已停止后才允许复位锁存 |
| STOPPING | 无普通操作 | 等待控制线程退出和停泵确认 |

## 3. 像素标定文件

配置中的 `calibration` 使用以下 schema。`calibration_image_sha256` 必须是原始标定图像的 SHA-256；运行比例与标定值相差超过三倍标定不确定度时配置会被拒绝。

```json
{
  "schema_version": 1,
  "calibration_id": "10x-cameraA-2026-08-26",
  "created_at": "2026-08-26T10:00:00+08:00",
  "magnification": "10x",
  "view_id": "chip-inlet-fov-1",
  "pixel_to_micron": 0.82,
  "uncertainty_um_per_px": 0.01,
  "calibration_image_sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "cross_view_cv_percent": 1.7
}
```

至少在视野中心和四角用可溯源标尺重复标定；报告每点重复性、拟合残差、比例不确定度以及跨视野 CV。目标直径不得传入检测候选或阈值选择。论文同时保存原始直径列表、筛选规则、原始 CV 和筛选后 CV。

## 4. 流量与响应延迟

软件中的 Q1/Q2 回读仅代表泵内部参数换算值，字段 `readback_kind=device_parameter_estimate`、`physical_flow_measured=false`。物理流量必须由以下至少一种方法独立验证：

1. 称重法：固定温度和液体密度，记录天平原始时间序列，线性拟合质量斜率并换算体积流量；
2. 经校准流量传感器：保存传感器序列号、校准证书、采样率和滤波规则；
3. 视觉阶跃法：仅作为芯片入口动态响应证据，报告图像标定和传播距离，不能替代绝对流量标定。

每次阶跃应使用同一个单调时间域记录：`command_sent`、`serial_reply_received`、`device_readback_verified`、`physical_response_started` 和 `physical_response_stable`。稳定判据必须在实验方案中预先定义，例如进入最终值 ±2% 并持续 2 秒。没有物理传感器数据时 `pump_response_delay_ms` 保持空值，不能用串口应答时间代替。

## 5. 相机性能口径

- 采集 FPS：按主机收到的相邻有效帧单调时间计算；
- 硬件丢帧：设备原始帧号缺口；丢包数单独累计，不与帧缺口混称；
- 处理 FPS：视觉算法完成结果的速率；
- 有效控制周期：产生一次可用于控制且未重复的完整视觉周期的间隔；
- 端到端识别延迟：硬件曝光时间戳到识别发布的差值。设备时间戳必须先与主机单调时钟做同步/拟合，不能直接混减。

“100 FPS”验收必须在目标相机、曝光、ROI、像素格式、SDK 和主机配置上连续运行至少 30 分钟，并同时报告以上五项、P50/P95/P99 延迟和内存峰值。

## 6. 故障注入验收

发布前至少执行并保存通信审计日志：

- Q1 成功、Q2 超时/校验错/地址错：两通道停泵，Q1 回滚尝试有记录，不得自动恢复；
- 停泵首三次失败：上层不得显示 STOPPED，独立安全线程持续重试；
- PID 线程任意位置抛异常：运行令牌立即失效并停泵；
- 停止与视觉完成并发：旧 `session_id/generation/period_id` 结果不得发送泵命令；
- 系统时间前跳和回拨：控制 `dt`、超时和新鲜度不受影响；
- 相机断线/重连：状态显示 RECONNECTING，重连后保留硬件帧号口径并重新下发、回读参数；
- 存储线程停止：队列尾部完全排空或明确记录丢弃数量。

软件单元测试不能替代上述硬件在环记录。所有实验数据应同时保存配置、标定记录、设备身份、通信审计日志、原始统计分布和软件提交版本。

## 7. 数据目录、迁移和保留

配置、日志、模型和内部数据库默认位于操作系统用户数据目录；Windows 为 `%LOCALAPPDATA%/MicrofluidicControlSystem`。测试或受控部署可用 `MCS_DATA_DIR` 覆盖。程序不在源码目录写运行数据，也不会在运行时改写 `TEMP`、`TMP` 或 GenTL/SDK 环境变量。

前端配置使用带 `schema_version` 的 JSON 包装，原来的根对象格式会自动迁移；每次覆盖前保留 `.bak`。扰动数据库使用 SQLite `user_version`，迁移前生成 `.pre_migration.bak`，缺失列通过显式迁移补齐。日志单文件上限 5 MiB、每次运行最多 5 个轮转分片；跨运行只保留最新 50 个文件且总量不超过 250 MiB。

实验原始图像、物理传感器数据和用户导出的 PID 数据不会自动删除。项目负责人应按实验编号归档后再清理，并验证备份可恢复；应用层容量清理不得替代实验数据管理制度。
