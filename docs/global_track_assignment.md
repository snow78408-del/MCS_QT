# 液滴轨迹的全局关联

2026-10-22：将运筹优化的二分图指派用于现有液滴跟踪，已接入
`NearestTracker` 和 `KalmanTracker` 共用的 `radius_gated_match()`。

原来的逐对贪心策略可能抢占另一条轨迹唯一可用的观测。例如轨迹位置为
4、8，检测位置为0、5，距离门限为5：先选4→5就会留下轨迹8；
全局分配4→0、8→5可以保留两条关联。

实现先沿用原距离和半径差门限筛选可行边，再最大化匹配数量，最后在相同
数量下最小化原有的位置/尺寸代价。虚拟未匹配列允许漏观测，禁止边使用无穷
代价，不能为了凑匹配数越过门限。无竞争候选直接返回，竞争候选使用已有
SciPy依赖的 `linear_sum_assignment`。距离与尺寸计算改为NumPy矩阵运算，
避免逐对Python循环；非有限坐标或半径不能参与匹配。

参考：[SciPy线性指派文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linear_sum_assignment.html)
及其引用的Crouse矩形指派算法。这里使用该优化思想和库接口，不引入新的检测模型。

原流程仍为管道注册/扶正→规则检测→跟踪→统计。检测端点、尺寸测量、轨迹
确认窗口、漏帧保留期限和泵控制约束均保持原语义。已有调用入口自动使用新
匹配方法，无需在实验方案中打开开关。

验证包括竞争关联的轨迹编号与确认状态、空集/矩形匹配、尺寸和距离门限、
非有限输入，以及80组小规模随机问题与穷举最优解对照。
离线回放使用两个各1000帧的历史连续序列，给新旧跟踪器相同的当前检测结果，
保留真实采集时间；记录逐帧匹配、累计轨迹数和跟踪耗时。

全局最优只针对既有代价和门限，并不保证真实身份最优。历史序列没有人工
轨迹真值，因此累计轨迹数、编号变化不能直接称为准确率；单帧边界精度也
不属于这次改动的收益。复现脚本、冻结旧代码、哈希、逐帧记录和测试日志在
数据目录的 `experiments/global_tracking_20261022/`。

本机独立复测结果（跟踪器整次update中位耗时，不含检测/图像读取）：

| 历史片段 | 跟踪器 | 原实现 ms | 新实现 ms |
| --- | --- | ---: | ---: |
| B1 70/20，1000帧 | Nearest | 0.1508 | 0.1377 |
| B1 70/20，1000帧 | Kalman | 0.2986 | 0.2861 |
| B2 70/25，1000帧 | Nearest | 0.1963 | 0.1439 |
| B2 70/25，1000帧 | Kalman | 0.3986 | 0.3433 |

两种跟踪器各2000帧的逐帧匹配集合与旧实现全部相同；这个回放仅支持
耗时改善与该数据上的行为一致性，不支持真实断轨率降低的结论。
竞争场景的改进由独立回归案例与穷举对照支持。
测试使用项目虚拟环境执行 `-m pytest -q -p no:cacheprovider`，隔离数据目录，
结果1256 passed、6 subtests passed（139.29秒）。
