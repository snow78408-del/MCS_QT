4. 修正结果命名、独立模型/有界修正模式区分、资格元数据和控制接线边界。

### B. 保持结果的提速（优先于新网络）

1. 对原VisionPipeline分段计时：墙线定位/注册、扶正、预处理、旧检测、学习修正、跟踪、统计。不存在的段明确N/A。
2. 检查已经跳过的无用分支是否对所有transverse_bounded输入等价；其余模式不得误跳。验证空图、低对比度、短宽ROI、斜管、几何缺失、异常长度、尺寸历史初始化与更新。
3. 优先减少重复图像转换/分配和不参与最终结果的计算。若缓存扶正映射，键包含原图形状、完整当前墙线与目标形状；几何变化立即失效，不可用旧墙线通过本帧定位检查。
4. 不在逐帧循环加载模型、编译网络或设置全局线程数；不能影响相机/GUI线程。推理模式、CPU线程数和编译策略必须在独立基准中比较。既有TorchScript实验出现弃用警告，且加速有限，不因“已试过”而强行部署。

### C. 在旧候选上提升边界准确度

1. 保留原候选数量和物相决定，学习模型只修正一对一可靠匹配的边界；无法匹配保持原结果并记录原因。
2. 针对模型新增开销，评估“小型端点局部窗口回归”或在几何/相位证据充分时的局部精修，训练数据仍来自人工笔迹。先证明收益再引入。
3. 低置信度、模型失效、明显新域、连续液丝或气泡候选只输出不确定诊断；不能自动放宽原限制换取召回。
4. 对失败例先判断是定位、扶正、候选生成、端点定位、跟踪还是标注不明确，避免让网络掩盖几何错误。

### D. 时序与真实运行代价

1. 选择有真实帧号/时间戳的已有连续片段，按原顺序回放；不得将82张离散图或1Hz样本称作高速连续视频验收。
2. 报告逐阶段和全可测链的中位、P95、P99、最大耗时、超时比例；至少3次重复、预热、batch=1，固定分辨率/ROI/线程、无绘图和有绘图分开。
3. 同一对象的长度波动必须经过可靠匹配才能评价；不同液滴之间的差异不能称为边界抖动。缺少真值时只报告稳定性，不能称动态准确率。
4. 禁止用多帧平均或旧帧结果冒充当前帧识别；若评估平滑，必须单列额外延迟与响应损失。

## 7. 验收指标（工程目标，不能冒充已达成）

- **结构**：扶正前不得调用学习边界修正；没有当前有效墙线时拒绝识别；原有物理标尺和控制资格链不变。
- **无学习提速路径**：相同输入下候选、有效性和尺寸历史与参考逻辑一致，非目标模式无回归；相对冻结基线P95下降至少20%作为本轮有意义收益目标。
- **有界学习修正**：漏检/误检不增加；共同匹配集端点或长度MAE至少改善10%，另一项不恶化，逐块列出失败。不能用粗标注要求亚像素“真值精度”。若达不到，保留影子候选，不默认切换。
- **延迟**：以同一机器原流水线为基线。有界修正版应力争P95不高于优化前原链，新增修正P95开销≤2ms；10ms/帧可作为100Hz处理预算检查点，但这是待商定目标，不是用户已确认的相机指标，也不保证采集到显示100fps。
- **样本资格**：现有12张只作回归；未见实验块的独立标签与真实负例不足时明确“不满足生产验收”。
- 若速度与精度无法同时满足，交付两方案的实测权衡和推荐，不掩盖退化。

## 8. 论文和开源参考：落实到具体决策

已核验一手来源（2026-10-22）：

1. Gardner等，Lab on a Chip 2022，DOI `10.1039/D2LC00462C`；作者代码：https://github.com/karl-gardner/droplet_detection 。参考对象检测的数据划分、标注增强、precision/recall评估与误检分析；其包封细胞/液滴场景不等于本机细长相差液滴，不能直接复用其物理尺寸假设。
2. Siemenn等，ACS AMI 2022，DOI `10.1021/acsami.1c19276`；https://github.com/PV-Lab/ML-Multiscale-Droplets 。已阅读segmentation.py，包含Otsu、距离变换、watershed和间隙伪影处理；其代码明确某些去伪影规则可能删真滴。参考ROI与分步处理，不用它替换已验证管道扶正或以形态学删除难例。
3. DropTrack基准：https://arxiv.org/abs/2301.08189 ，期刊DOI `10.1140/epje/s10189-023-00290-x`。作者比较YOLO与DeepSORT分段耗时，跟踪开销可能抵消检测提速。参考分段基准方法；本项目已有跟踪器，未证明需要外观重识别前不新增DeepSORT。
4. 轻量端侧实现：https://github.com/taltechloc/sw-open-droplet-analysis 。作者提供YOLOv4-tiny/OpenCV DNN方案与自报性能；参考轻量推理部署，不把其树莓派/分类数据上的毫秒数或mAP移植到本机。

阅读相关实现而不是只引用标题；标明哪些思想实际采用、哪些不适用。引用代码前核对具体仓库及依赖许可证，保留要求的归属说明；本任务书没有复制上述源码。不得运行外部仓库的相机/设备入口。
