# 标定方案：先验证测量，再辨识模型

更新：2026-09-20。本版替代原文中相互冲突的实验要求。旧版本逐字节快照保存在 `output/document-consistency-20260920/`，文件清单及 SHA-256 见其中 `manifest.json`。

依据：[结果审计](deepseek_results_audit_20260919.md)、[离线复算](offline_flow_review_20260919.md)、[证据分级](plant_model_revision_20260919.md)。本文件是待现场确认的实验设计，不是已经验证的无人值守执行流程。

## 1. 目标与当前边界

目标是建立明确输入口径的“命令流量 → 液滴等效尺寸”模型，并通过新采集数据的独立验证。

当前历史记录不足以辨识可靠增益；像素几何和候选运动可用于离线分析。相别、观测通道实际宽高、独立像素标尺、注射器配置对应关系和实际出液量仍未确认。不能据旧报告调整泵参数、按 0.061 缩放增益或生成可加载的标定结果。

## 2. 基础核对：先记录，再实验

| 核对项 | 需要保存的证据 | 不能替代它的材料 |
| --- | --- | --- |
| 两路相别与流路 | 储液容器内液体身份、CH1/CH2 接管照片、芯片入口到观测窗及池的连接关系 | 指令流量比例、亮度占空比、交换通道后的变化方向 |
| 像素标尺 | 同一成像配置下的独立标尺、原图、测量区间、单位和不确定度 | 假定观测通道与生成区同宽 |
| 观测通道宽高 | 对应当前芯片和观测段的可追溯规格或独立测量 | 另一芯片深度、俯视宽度直接充当深度 |
| 注射器与代码 | 实际型号及其内径依据、当前泵代码、该泵型号的厂商代码表或面板参数 | 单独的 0x21 回读值或通用内径表 |
| 两路实际输送 | 分路测量记录、时长、体积或质量及密度、重复性、负载条件 | 泵内部由配置换算出的流量 |

标尺来自经验证的通道规格时，注明其来源及不确定度；不得把假定通道宽度算出的标尺再用于证明同一宽度。历史标尺数值不同本身也不能证明出错，需核对光学配置。

相别先通过液体身份和接管追溯确认。仅凭单开或对调通道后图像发生变化，不能唯一证明相别；需要示踪时，先明确它是否改变体系及如何与原工况对应。

## 3. 独立出液量核对

分别为两路设计测量，在适用的负载和流路条件下记录起止时间、收集量和泵配置。称重时使用对应液体密度，并记录收集损失、背景变化和仪器分辨率；推杆位移换算则必须有实际内径依据。

每路分别得到 `r_i = Q_actual_i / Q_cmd_i` 及其重复性。不能假定两路同比缩放，不能把某次短时启动阶段的比值直接当作固定泵系数；脱离芯片的出液结果也不能自动代表接入芯片后的动态输送。

持续时间由分辨率、可用行程、液量和工况确定，不再承诺“一分钟完成”。本版不预设指令倍率或要求更换注射器。测量和任何配置变更都应分别记录，变更后重新核对。

## 4. 完整响应采集

先验证测量链，再从一组经确认的工作点附近做单路小变化，另一路保持不变。具体流量、阶跃幅度和最长运行时间由现场确认，不沿用旧文硬编码的网格。

记录应覆盖变化前基线、变化全过程和稳定平台；安排正反向重复与返回基线，并将后续独立验证数据留出。若测试期间发生补液或配置变化，将其标为独立事件和分段边界，不拼成一个连续响应。

必须记录：

- 帧号、设备时间戳（若可获取）、主机接收时间、丢帧与异常。
- 同步命令时刻、配置/流量回读、启动/停止结果。
- 曝光和帧率设置及可用回读、图像和流路配置。
- 原始图像或保留原采样时序的通道图像片段、算法版本、每窗质量与混叠状态。

不能仅保存导出速度序列和稀疏截图，否则无法重新排查混叠、边界错误或丢帧。先核算存储容量；需要裁剪或降采样时，记录变换并验证它不会丢失所需测量信息。

稳定性由噪声水平、斜率、持续时间、重复性及观测质量共同判断，预先声明判据。现有数据不能确定固定等待 35 秒、5 分钟或 10 分钟，也不能证明一个通用斜率阈值。达到采集上限仍无平台时，保留暂态数据并记录未达到稳态，不强行给出稳态增益。

候选速度保持同一混叠分支并不证明其真实值。独立速度约束、帧率/时间基准和人工边界验证要分别补证；方向锁定或增加 frame gap 本身不能保证解除混叠。当前 `ALIAS_UNRESOLVED` 数据不作为真实流速或实际流量。

## 5. 模型选择与输入定义

先比较局部静态模型和带动态的候选模型。纯延迟、一阶、二阶或其他形式都只是候选；目前没有证据锁定“分钟级泵动态”“一阶测量滞后”或池的位置。图像变化不能单独归因于泵本体。

若输入使用 `Q_cmd`，稳定且适用的输送比例可能已包含在辨识的命令域对象增益中；这不保证闭环可用性，也不允许再次套用固定倍率。若改用 `Q_actual`，必须明确其测量来源和时序。区分对象增益与控制器增益。

等效球直径是软件体积模型的口径，不能等同于塞状液滴轴向长度。人工标注与算法结果应使用同一帧、同一弯月面定义并附不确定区间，不能配对前段长度与末段速度。

## 6. 容量与执行条件

根据实测输送、剩余液量、推杆行程和计划时长确定实验分段。自动补液不是本轮已验证能力，也不是现有数据能推出的硬要求；可先安排可完整覆盖的短实验和人工恢复。不要从协议存在 withdraw/repeat 就推断现有流路允许自动补液。

现场采集前逐个检查所用脚本的启动、超时、异常、停止与回读路径。不能笼统声称所有脚本都已保证安全停机。本文不提供无人值守硬件启动命令。

## 7. 现有离线入口

以下命令只读取已有录像，输出目录必须尚不存在：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/review_periodic_flow.py --video output/crops/ref_video.npy --rate 101.613 --time-source reference_report_rate_not_independently_verified --output output/reference-review-new --window 30 --step 30
```

默认输出为候选位移；详细参数与混叠边界见 [离线复算说明](offline_flow_review_20260919.md)。`tools/plant_geometry_solver.py` 是未验证的情景计算器，不是测量验收入口。两个既有 `geometry-solve-*.json` 原文件没有 `validity` 字段；保留原样，外部状态见 `output/legacy_result_status_20260920.json`。

## 8. 验收与交付

| 项目 | 口径 |
| --- | --- |
| 独立验证误差 | 沿用项目 MAE ≤ 2 µm、NRMSE ≤ 0.25 的门槛，并明确归一化定义；必须使用未参与模型选择的新数据 |
| 重复性 | 计划同刺激至少 3 次；报告分布、极差及时间漂移，不用单次结果代替 |
| 增益方向 | 报告置信区间与独立会话数量，避免把同一会话内重复当成独立样本 |
| 动态参数 | 仅在观测支持时报告延迟和时间常数，不能辨识时明确留空 |
| 标定文件 | 使用现有应用验证流程；不得手工将 validated_for_pi / validated_for_mpc 置真 |

交付独立标尺/通道资料、两路相别与配置对应表、实际出液量记录、带时间基准的原始响应、人工标注、候选模型比较与独立验证结果。

旧扫描与历史标定继续保留，当前不能直接充当稳态增益标定；不得把它们统称为全无价值或断言全部由暂态导致。离线诊断可继续，新的控制参数等待上述证据与验收。
