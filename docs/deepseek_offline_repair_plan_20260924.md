## 二、先做三项代码修复（必做）

### A. 统一生产与诊断测量入口

现状：DropletDetector.detect() 不传 channel_width_px，诊断工具绕过公开接口并传 min(gray.shape)。相同画面可能使用不同长度门槛。

要求：
1. 建立公开的、显式传递扶正像素几何的入口，生产路径和相关诊断工具共用。优先沿用现有测量上下文，不另建一套检测算法。
2. 横向宽度来自本帧扶正几何，明确轴向、输出尺寸、像素索引跨度和几何长度的定义。禁止继续用 min(shape) 猜方向；禁止把名义 50 µm 或默认倍率当作本帧像素宽度。
3. 不建议仅把瞬时像素宽度固化为持久配置：分辨率、ROI 或墙线变化后可能失效。若存在配置默认值，明确其适用范围和失效条件。
4. 几何未认证时可给出明确标注的诊断候选，但不得伪装为可用于控制或物理标定的有效测量。保持像素、轴向长度、体积等效直径及物理单位的既有闸门。
5. 同一输入帧、同一生效配置、同一几何，经生产入口和诊断入口必须得到一致的候选、门槛和拒绝理由。

回归至少覆盖：短液柱、几何变化、未知/非法宽度、未验证标尺、真实检测器的生产/诊断一致性。不要只用检测器桩证明接线。

### B. 严格定位模式保持

现状：service 配置局部副本启用严格模式，几何设置重传不含该键的配置，适配器缺省 False，可能静默关闭。

要求：明确完整配置与局部更新的语义；几何参数更新不能隐式关闭严格定位。若允许显式切换，必须经清晰的公开接口与状态限制，并留下可查询状态。避免只在某一调用点补键而保留其他静默关闭路径。

回归使用真实 service/adapter 配置链、设备桩：配置严格模式 → 修改几何 → 严格模式仍生效 → 最新帧无有效定位仍拒测。另验证初始化、完整配置重置和显式切换的预期行为。

### C. 退出状态与停止结果

现状：入口仅凭 stop.verified 返回成功；stop=None 会抛 AttributeError。

要求：统一相关入口的结果解释，分别报告运行完成、测量验收、停止状态。退出码 0 只表示该入口预先声明的任务目标成功；不能把成功停泵当成实验通过。诊断采集完成但测量未验收的语义必须明确，不能混用。

STOP_UNVERIFIED 保持最高优先级；stop=None 表示未进入停泵路径或没有停止证据，按上下文表达，不能伪造 STOPPED。启动前失败、测量前提失败、采集异常、写盘异常、用户中断、停泵失败均保留根因，不由收尾异常覆盖。

回归包含：FAILED + stop=None；PREMISE_REJECTED + 已停泵；成功任务 + 已停泵；STOP_UNVERIFIED；未触碰设备的预检失败。不得为了测试通过改变泵安全行为。

## 三、用现有连续录像检查真实能力（必做）

材料优先使用 E02/R1 与 E03/B1 的原始录像和 frames.ndjson。E04/E05 没有同步录像，不得用 B1/R1 的时间变化替它们证明对象身份。

1. 先检查录像与帧记录的对应约定。按记录中的真实采集时间取片段，不用帧序号/100 代替真实时间。
2. 预先登记取样规则和片段列表。至少选 4 段、每段 3–5 秒，覆盖 R1/B1、不同工况或时段；包含低可见度或预期拒测段，不只挑通过样本。没有合适场景就报告缺口，不伪造类别。
3. 连续送入修复后的生产定位/测量路径，保留有界历史，不对每一帧重新创建定位器。任何暖机前缀需列出；禁止借未来帧认证过去帧。
4. 保存逐帧结果和可查看的短片/对照图：原图、定位墙线、真实扶正范围、候选、接受/拒绝与原因。叠加区域必须使用正确逆变换，且绑定同一帧。
5. 按片段分别报告：输入帧数、时间跨度、缺帧/时间异常、定位状态分布、有效测量帧数、至少一个接受候选的帧数。没有跟踪就不报告独立对象数。
6. 比较修复前后时必须使用相同片段、配置和时间范围，列明唯一变化。不能把非零计数称为精度提升。
7. 能看图就做明确标注的人工核对，列出可判断与不可判断对象；不能看图就明确声明，将绑定帧号的材料交给 Codex 目视。不得再把像素统计称为人工盲标。

本轮不要求“必须定位成功”。若全部失败，准确定位证据瓶颈并保留片段即可；这意味着测量能力仍未验收，不能放宽判据凑通过，也不能继续上机消耗液体。

## 四、运行追溯与帧绑定（必做）

### 代码与生效配置

- 新运行保存相关源码快照、逐文件 SHA-256、清单版本和总指纹；覆盖实际入口及定位、扶正、检测、配置、记录/时钟与生命周期依赖。说明清单范围，不能只有入口文件的哈希。
- Git 提交号和工作区状态作为辅助，不能代替未提交/未跟踪代码快照。记录 Python、关键依赖版本及脱敏后的运行参数。
- 生效配置在默认值、配置文件与命令行覆盖合并完成后保存：检测参数、严格模式、墙线来源/认证状态、图像尺寸、标尺/深度声明、成像设定与回读来源、采样策略。未知值留空并写原因，不能把设定当实测。
- 运行中若允许配置变化，生成新配置版本和生效帧边界；否则明确禁止。测量行引用当时的版本。
- 快照或配置清单写入失败时，新现场运行入口应在硬件动作前拒绝启动；离线模式可输出明确的追溯失败。检查快照前后源文件变化，避免把混合文件版本当成确定运行版本。

### 一帧到底的引用

- 每次采集有独立 session/capture 标识；软件序号、硬件帧号、采集时间分别保存，不相互冒充。硬件帧号可能重启或回绕，不能单独当全局主键。
- 录像记录使用确定的容器路径和解码帧索引；原始块记录使用路径、offset、nbytes、shape、dtype；静帧记录文件路径和哈希。路径相对会话目录，避免搬迁后失效。
- 原图、测量行、扶正图与叠图共享明确的 source_frame_ref；转换记录包括几何版本、坐标系和变换矩阵。缺失图像引用就显式标缺失，不用邻近静帧或文件序号猜配对。
- 增量写盘并区分已提交记录与待写数据。写盘中断后已保存帧可恢复核对，不能给未保存帧生成“可读取”引用。完整大录像哈希放在收尾或离线校验，避免在逐帧关键路径增加无界开销。
- 旧记录保持不变。允许生成独立 sidecar 索引，注明是后来重建以及证据限制；不得补造 E04/E05 的历史源码哈希或精确静帧绑定。

提供离线核验命令：验证快照/配置哈希、检测引用缺失或篡改、从给定测量行找回确切源帧。核验不能导入即连接设备。

## 六、测试与验收

先保存最小失败反例，再修复；执行受影响测试。因涉及公共流程与状态，完成后执行一次隔离环境的完整 pytest，记录实际命令与日志。不以不断增加合成测试数量替代真实录像证据。

最终分别给结论：
1. 软件缺陷修复是否通过；
2. 已有真实连续录像中的定位/测量是否通过或仍证据不足；
3. 新记录的可追溯性是否通过；
4. 现场设备与物理标尺仍未验证哪些项。
