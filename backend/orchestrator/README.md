# backend/orchestrator

本目录用于耦合主系统，是后端主流程调度入口。

## 1. 职责
- 统一接收前端配置并管理系统状态。
- 调度图像识别模块、PID 反馈模块、泵硬件交互模块。
- 管理初始化流程、控制循环流程、停止流程和异常流程。
- 向前端输出统一系统快照（识别状态、泵状态、控制状态、错误信息）。

## 2. 实时视频模式流程
1. 接收前端配置。
2. 准备实时视频输入。
3. 启动图像识别模块。
4. 连接泵硬件并完成探测/回读。
5. 下发并校验初始 Q1/Q2。
6. 初始化完成后，用户点击开始运行。
7. 可选：先运行安全 BO 寻找工作点并经过稳定保持，再切换 PID。
8. 周期读取识别结果并调用 PID。
9. 根据 PID 输出执行：
- 冻结：保持当前流速。
- 建议停机：执行停泵保护并进入异常/停止状态。
- 正常：下发新流速并回读校验。
10. 前端周期刷新识别、泵和控制状态。
11. 用户停止时，停止控制循环、停泵、停止识别，进入 `STOPPED`。

## 3. 本地视频模式流程
1. 接收前端配置。
2. 准备本地视频输入。
3. 启动识别处理并输出识别结果。
4. 只做识别与显示，不做泵控制下发。
5. 视频处理结束后进入 `STOPPED`。

## 4. 控制循环流程（实时模式）
1. 定时获取识别快照。
2. 构造 PID 输入（识别指标 + 目标参数 + 泵状态 + dt）。
3. 调用 PID 反馈模块。
4. 判断输出分支：
- `freeze_feedback=True`
- `suggested_stop=True`
- 正常控制输出
5. 执行泵下发与回读校验（正常分支）。
6. 更新系统快照供前端刷新。

## 5. 异常处理流程
- 识别无效：不更新控制输出，保持当前泵流速。
- PID 冻结：保持当前泵流速并显示冻结原因。
- PID 建议停机：调用泵模块停泵并进入 `ERROR` 或 `STOPPED`。
- 泵通信异常：执行停泵保护并进入 `ERROR`。
- 用户主动停止：安全停机后进入 `STOPPED`。

## 6. 状态流转
- `IDLE`：空闲未配置。
- `CONFIGURED`：已接收参数配置。
- `VIDEO_READY`：视频源已准备。
- `INITIALIZING`：初始化中（设备连接/回读/初始下发）。
- `INITIALIZED`：初始化完成，可开始运行。
- `OPTIMIZING`：BO 独占泵写权限并搜索安全工作点。
- `STABILIZING`：保持 BO 最优点，等待有效稳定窗口。
- `RUNNING`：运行中。
- `PAUSED`：暂停中。
- `STOPPING`：停止中。
- `STOPPED`：已停止。
- `ERROR`：异常状态。

推荐主路径：
`IDLE -> CONFIGURED -> VIDEO_READY -> INITIALIZING -> INITIALIZED -> OPTIMIZING -> STABILIZING -> RUNNING -> STOPPING -> STOPPED`

也可跳过 BO，从 `INITIALIZED` 直接进入 `RUNNING`。详细安全门控见 `docs/bo_pid_feedforward.md`。

## 7. 目录关键文件
- `service.py`：耦合层主服务实现（流程调度与循环执行）。
- `flow.py`：系统流程骨架定义（状态 + 阶段方法）。
- `models.py`：系统配置与快照数据模型。
- `state.py`：系统状态枚举。
- `config.py`：耦合层运行参数配置。
- `vision_adapter.py`：视觉适配器协议与通用封装。

## 8. 注射泵事务后的反馈等待

- 仍使用原 7.5–30 秒控制周期范围和统一双通道事务，不引入频率反馈或新泵协议。
- 成功完成双通道更新及校验后，以主机收到事务结果的单调时间作为等待起点。失败、取消或停止期间的事务不提交 PID 内部状态。
- 已有通过独立验证的标定时，暂以 `保守延迟 + 3 × (时间常数 + 时间常数不确定性)` 估算响应等待；这是近似 95% 的一阶响应时域估计，不是实测稳定证明。原标定延迟从命令开始计算，因此从事务完成后再等待是有意偏保守的。
- 无可用标定时，等待一个设定周期作为未验证的保守回退；这不会绕过原有标定授权检查，也不证明该周期适合设备。
- 必须等待一个完整、有效的调整后尺寸窗口，且构成轨迹尺寸的最早测量时间不能早于等待截止。最早时间采用该轨迹首次有效尺寸观测，属于保守下界。混合窗口及过渡数据保留给监测，不从显示数据中删除。
- 缺少时间来源时冻结，不能用最新帧时间给历史平均值重新标记。普通等待不阻止安全检查、暂停、停止或故障处理。
- PID 在候选副本上计算；仅事务成功且生命周期仍有效时提交积分等状态。恢复更新时积分最多使用一个设定周期，微分仍使用实际 dt，不把跳过时段一次性补积分。
- `ControlSnapshot` 增加 `basis_command_id`、`command_id`、`command_completed_monotonic`、`feedback_ready_after`；`[PID][BASIS]` 与 `[PID][POST_COMMAND]` 日志关联窗口、采集来源和命令。它们不是独立物理流量测量。
- 反馈等待消费已有标定结果；自动标定的时间门控见下节。改变执行节奏后的闭环效果仍需无硬件回放及受控上机复核。

## 9. 自动标定的时间门控与基线复用

- 默认改为 8 组试验：Q1、Q2、组合方向各一次正反阶跃（6 组），加两组独立验证。原有效液滴数要求、独立验证门控与拟合方法不变。已有保存配置不自动覆盖，可在界面点击“一次建模（8 组）”切换；运行期间不可切换。减少重复意味着重复性证据减少，正式论文实验需另做重复验证。
- 阶跃检测到连续两滴同向超阈值的可信响应后，不再硬等 30 秒；稳定窗口必须始于响应起点和事务完成之后，并满足原样本数、稳定阈值及默认 3 秒持续时间。基线仍保留可配置的 30 秒等待，不能仅凭稳定就确认已从上一阶跃返回。高频液滴不会只因凑足数量就立即结束观察。
- 未检测到响应时观察至默认 60 秒，稳定窗口与观察时间并行累计，不额外再等 3 秒；不稳定则继续观察。记录含义为本次观察未检测到可信响应，不能排除更晚到达的变化。上述时间是可配置观察条件，不是设备实测参数。
- 响应记录保留命令开始后的过渡数据用于辨识，等待门控仅限制结束判定。基线只接受等待截止后的液滴。
- 上一次成功写入已恢复相同基线时，仍重新读取两路运行状态与流量设定值；确认一致才跳过重复写入，并保留原事务完成时间。状态无法验证或生命周期失效则终止，流量不一致则按原事务恢复。读回设定值不代表实际到芯片流量，复用后仍需视觉基线稳定检查。
- 等待期间继续视觉采集，保留原停止与视觉存活超时机制。减少重复写入不保证总耗时缩短；增加观察时长后首次完整标定可能更久，仍需操作员在场。
