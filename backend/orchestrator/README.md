# backend/orchestrator

本目录用于耦合主系统，是后端主流程调度入口。

## 1. 职责
- 统一接收前端配置并管理系统状态。
- 调度图像识别模块、PID 反馈模块、泵硬件交互模块。
- 管理初始化流程、控制循环流程、停止流程和异常流程。
- 向前端输出统一系统快照（识别状态、泵状态、控制状态、错误信息）。

## 2. 实时视频模式流程
1. 接收前端配置。
2. 准备实时视频输入。
3. 启动图像识别模块。
4. 连接泵硬件并完成探测/回读。
5. 下发并校验初始 Q1/Q2。
6. 初始化完成后，用户点击开始运行。
7. 可选：先运行安全 BO 寻找工作点并经过稳定保持，再切换 PID。
8. 周期读取识别结果并调用 PID。
9. 根据 PID 输出执行：
- 冻结：保持当前流速。
- 建议停机：执行停泵保护并进入异常/停止状态。
- 正常：下发新流速并回读校验。
10. 前端周期刷新识别、泵和控制状态。
11. 用户停止时，停止控制循环、停泵、停止识别，进入 `STOPPED`。

## 3. 本地视频模式流程
1. 接收前端配置。
2. 准备本地视频输入。
3. 启动识别处理并输出识别结果。
4. 只做识别与显示，不做泵控制下发。
5. 视频处理结束后进入 `STOPPED`。

## 4. 控制循环流程（实时模式）
1. 定时获取识别快照。
2. 构造 PID 输入（识别指标 + 目标参数 + 泵状态 + dt）。
3. 调用 PID 反馈模块。
4. 判断输出分支：
- `freeze_feedback=True`
- `suggested_stop=True`
- 正常控制输出
5. 执行泵下发与回读校验（正常分支）。
6. 更新系统快照供前端刷新。

## 5. 异常处理流程
- 识别无效：不更新控制输出，保持当前泵流速。
- PID 冻结：保持当前泵流速并显示冻结原因。
- PID 建议停机：调用泵模块停泵并进入 `ERROR` 或 `STOPPED`。
- 泵通信异常：执行停泵保护并进入 `ERROR`。
- 用户主动停止：安全停机后进入 `STOPPED`。

## 6. 状态流转
- `IDLE`：空闲未配置。
- `CONFIGURED`：已接收参数配置。
- `VIDEO_READY`：视频源已准备。
- `INITIALIZING`：初始化中（设备连接/回读/初始下发）。
- `INITIALIZED`：初始化完成，可开始运行。
- `OPTIMIZING`：BO 独占泵写权限并搜索安全工作点。
- `STABILIZING`：保持 BO 最优点，等待有效稳定窗口。
- `RUNNING`：运行中。
- `PAUSED`：暂停中。
- `STOPPING`：停止中。
- `STOPPED`：已停止。
- `ERROR`：异常状态。

推荐主路径：
`IDLE -> CONFIGURED -> VIDEO_READY -> INITIALIZING -> INITIALIZED -> OPTIMIZING -> STABILIZING -> RUNNING -> STOPPING -> STOPPED`

也可跳过 BO，从 `INITIALIZED` 直接进入 `RUNNING`。详细安全门控见 `docs/bo_pid_feedforward.md`。

## 7. 目录关键文件
- `service.py`：耦合层主服务实现（流程调度与循环执行）。
- `flow.py`：系统流程骨架定义（状态 + 阶段方法）。
- `models.py`：系统配置与快照数据模型。
- `state.py`：系统状态枚举。
- `config.py`：耦合层运行参数配置。
- `vision_adapter.py`：视觉适配器协议与通用封装。

## 8. 注射泵事务后的反馈等待

按帧批次控制启用时，以下物理反馈等待仍适用；原时间窗调度由“采集 → 分析 → PID → 事务”的批次调度取代，控制周期仅保留为循环间隔下限。

- 仍使用原 7.5–30 秒控制周期范围和统一双通道事务，不引入频率反馈或新泵协议。
- 成功完成双通道更新及校验后，以主机收到事务结果的单调时间作为等待起点。失败、取消或停止期间的事务不提交 PID 内部状态。
- 已有通过独立验证的标定时，暂以 `保守延迟 + 3 × (时间常数 + 时间常数不确定性)` 估算响应等待；这是近似 95% 的一阶响应时域估计，不是实测稳定证明。原标定延迟从命令开始计算，因此从事务完成后再等待是有意偏保守的。
- 无可用标定时，等待一个设定周期作为未验证的保守回退；这不会绕过原有标定授权检查，也不证明该周期适合设备。
- 必须取得一个完整、有效的调整后尺寸窗口，构成轨迹代表尺寸的实际样本时间不得早于等待截止。起止时间仅来自仍参与中位数的测量帧，不再以轨迹首次出现时间扩大等待。混合窗口及过渡数据保留给监测。
- 缺少时间来源时冻结，不能用最新帧时间给历史平均值重新标记。普通等待不阻止安全检查、暂停、停止或故障处理。
- PID 在候选副本上计算；仅事务成功且生命周期仍有效时提交积分等状态。恢复更新时积分最多使用一个设定周期，微分仍使用实际 dt，不把跳过时段一次性补积分。
- `ControlSnapshot` 增加 `basis_command_id`、`command_id`、`command_completed_monotonic`、`feedback_ready_after`；`[PID][BASIS]` 与 `[PID][POST_COMMAND]` 日志关联窗口、采集来源和命令。它们不是独立物理流量测量。
- 反馈等待消费已有标定结果；自动标定的时间门控见下节。改变执行节奏后的闭环效果仍需无硬件回放及受控上机复核。

### 采样和命令审计修正

- 本次不新增硬性等待下限，不叠加固定秒数；已有标定响应估计、无标定回退和标定早期响应结束规则保持。
- 采集时间缺失、非有限、未来时间及重复/乱序图像不能补成识别完成时间。处理异常立即发布无效识别状态。完成时间单独保存为 `processing_completed_monotonic`。
- `measurement_sample_start/end` 表示参与窗口代表尺寸的实际测量起止时间。标定逐滴事件也携带样本起点，混合旧测量不得用于调整后的稳定判定；没有逐滴时间来源的事件不参与标定。
- PID 微分时间基准取已接受的尺寸采样时刻；等待、失败、取消不会推进历史时钟或提交积分。积分仍最多累计一个设定周期，不补算跳过时段。
- 双通道调流事务（PID、BO、标定）使用 `[PUMP][COMMAND]` JSON 事件写入已有日志通道。每次尝试先分配编号，包含来源状态、运行代次、请求值、窗口及样本时间；随后记录 dispatching、transaction_result 和 verified/failed/cancelled/error/rejected。通信层先停泵并核验，再写入参数并回读，最后重新启动并核验；仅完整事务通过才算新流量生效。dispatching 与单独的参数回读均不代表流量已切换。
- 事务结果记录两路参数换算值、错误、回滚和安全停机验证；生命周期取消后仍保留已返回的硬件结果，不冒充有效控制提交。`FlowUpdateResult.command_id` 与成功等待的编号保持一致，失败尝试也占用编号。

## 9. 自动标定的时间门控与基线复用

- 自动标定窗口独立提供“基线等待时间” `baseline_wait_s`，范围 0–3600 秒，首次默认 30 秒，保存键为 `plant_calibration_baseline_wait_s`。旧配置缺省时沿用原响应等待；修改基线等待不改变响应观察时间。0 仅取消固定等待，有效液滴数、持续稳定和存活看门狗仍生效；过短可能采入上一阶跃的迟到响应。

- 默认改为 8 组试验：Q1、Q2、组合方向各一次正反阶跃（6 组），加两组独立验证。原有效液滴数要求、独立验证门控与拟合方法不变。已有保存配置不自动覆盖，可在界面点击“一次建模（8 组）”切换；运行期间不可切换。减少重复意味着重复性证据减少，正式论文实验需另做重复验证。
- 阶跃检测到连续两滴同向超阈值的可信响应后，不再硬等 30 秒；稳定窗口必须始于响应起点和事务完成之后，并满足原样本数、稳定阈值及默认 3 秒持续时间。基线仍保留可配置的 30 秒等待，不能仅凭稳定就确认已从上一阶跃返回。高频液滴不会只因凑足数量就立即结束观察。
- 未检测到响应时观察至默认 60 秒，稳定窗口与观察时间并行累计，不额外再等 3 秒；不稳定则继续观察。记录含义为本次观察未检测到可信响应，不能排除更晚到达的变化。上述时间是可配置观察条件，不是设备实测参数。
- 响应记录保留命令开始后的过渡数据用于辨识，等待门控仅限制结束判定。基线只接受等待截止后的液滴。
- 上一次成功写入已恢复相同基线时，仍重新读取两路运行状态与流量设定值；确认一致才跳过重复写入，并保留原事务完成时间。状态无法验证或生命周期失效则终止，流量不一致则按原事务恢复。读回设定值不代表实际到芯片流量，复用后仍需视觉基线稳定检查。
- 等待期间继续视觉采集，保留原停止与视觉存活超时机制。减少重复写入不保证总耗时缩短；增加观察时长后首次完整标定可能更久，仍需操作员在场。

## 10. 按帧批次控制

`SystemConfig.control_batch_enabled` 对旧配置默认关闭；操作员在新增按钮中保存时启用。`control_capture_frames` 和 `control_analysis_frames` 默认均为 5，校验 `5 ≤ 分析 ≤ 采集 ≤ 64`，配置和快照沿用既有存储通道。

在 RUNNING 状态，每次 PID 周期请求一个新批次，拒绝请求之前的图像。采满 N 帧后才把末尾连续 M 帧提交识别；全部处理完成发布唯一 `control_batch_id`。控制线程只消费对应完整结果，经原质量、时效、标定、反馈等待和安全检查后调用原 PID／双泵事务路径。该决定完成前不请求第二批，不积压调流命令。

批次请求前等待已有物理响应门控和循环间隔。等待批次时使用条件事件并持续安全心跳，120 秒不完成触发原故障停机路径。暂停、停止、运行代次变化使旧请求失效；帧批次失败只发布无效测量。单批原图内存预算 256 MiB，超限拒绝该批并提示减少帧数或分辨率。

`configure_control_batch(N, M)` 通过替换配置对象更新下一批，正在采集／分析的批次保持原帧数。预览与连续过线计数独立运行；BO、稳定保持及自动标定保持原连续观察方式。上一周期识别帧展示本批全部 M 帧，包括最后一帧。

## 11. 独立前馈配置

`SystemConfig.target_feedforward_enabled` 与 `disturbance_feedforward_enabled` 均默认 false，初始化时独立传递给控制器。已验证的生成区标定提供目标前馈的 Q1/Q2/尺寸基准及局部对数模型，但不授权旧扰动前馈增益。初始化清除上一次模型授权，缺失或不合格标定不能残留启用状态。

`ControlSnapshot` 和 `PIDCommand` 分别记录 `target_feedforward_*`、`disturbance_feedforward_*` 的输出、参与状态和原因，原 `feedforward_output` 保留为合计。前馈计算完全在 pid_control 内执行，不增加第二条泵写入通道；结果仍只在成功且生命周期有效的事务后提交。运行中目标改变沿用目标版本检查，计算期间发生目标变更的旧命令仍被丢弃。

实际标定文件的获取和两种 JSON 的区别见 [标定文件说明](../../docs/calibration_files.md)。

## 12. 工况稳定性与无响应保护

RUNNING 的有效、完整调整后观测先经过 `ResponseGuard`，再进入扰动采样、PID 与唯一泵事务路径。稳定但未检测到变化是正常观测，不证明零增益或气泡；界面通过原控制原因栏显示保持、恢复观察、无响应限额和超时原因。

- 目标误差在已有直径死区内，或候选流量完全不变时，不重复写泵。
- 尺寸窗口两倍标准差或三个窗口均值的跨度超过容差时暂停反馈。容差为 `max(response_guard_tolerance_um, 2 × μm/px)`；这是暂定工况策略，并非本次失败标定辨识出的常数。
- 不稳定/无效观测不更新 PID、积分或扰动学习。恢复需要三个全新稳定窗口且跨越 `response_guard_recovery_s`，恢复首步以已回读流量重置工作点、积分时间为零并限制步长。暂停/恢复清除旧稳定证据，不补算暂停时间；保留无响应限额。
- 仅成功且生命周期有效的实际流量变化计为尝试，每个命令只评估一次响应。稳定但无响应后允许有限重试，沿用 PID 分配器进行限幅和抗积分饱和，不在输出端额外裁剪。达到限额后保持并提示检查；迟到的可检测变化可解除无响应保持，不等同于已确认正确的控制方向。
- 运行策略默认：容差 4 μm、恢复跨度 15 s、持续异常超时 120 s、最多 3 次未响应命令（含首步）、重试/恢复每路每步最多 1 μL/min、重试两路绝对变化累计最多 4 μL/min（首步不计入重试预算）。这些值由 `OrchestratorConfig` 明确配置并校验，需稳定工况数据和设备复核；原泵边界及更严格的已有步长限制始终有效。
- 原安全检查优先；通信失效仍安全停机。工况持续异常达到超时也停止；正常无响应限额仅停止自动追调，不声称硬件故障。
- 自动标定保留稳定低响应样本，不要求每次阶跃都检测到变化。基线等待截止后最多再等 180 s；响应默认低响应观察期后最多再等 180 s。正数 `maximum_step_duration_s` 明确限制事务完成后的响应时长，0 使用上述有限默认值。超时结束本次标定，保存标注 `incomplete` 的诊断 JSON 到既有用户 `calibrations` 目录，基线仅保存最近观察尾窗，响应保存已采集曲线。该文件不能作为标定加载；稳定后需重新标定，不自动重复操作泵。
- 独立验证阈值和授权不变，不按预测残差挑选或删除试验。未响应通道的零分配只表示本记录暂不使用该方向，不是认定物理增益为零。

默认非线性标定不会因组合阶跃无单次可检测响应而提前结束，仍完成预定验证。
拟合后不可辨识时进入 STOPPED，保留数据；停泵失败仍进入 ERROR。
所有标定失败/中止会在安全清理之后保存已完成测量和当前未完成试验，路径写入
快照 `measurements_path` 和弹窗。保存期间禁止再次启动标定；磁盘写入失败单独提示。
超时的即时诊断只保留基线尾窗，结束归档还包含本轮收集的有效基线观察。

## 13. 以验证通过作为自动标定成功条件

采集完成只生成候选模型。桌面流程要求 PI 独立验证通过，
并确认安全停泵，才发布 completed 并允许保存应用。验证门槛不变。

每次只执行已确认的一轮建模与独立验证，计划上限为建模重复数 × 6 + 验证重复数 × 2。
不自动增加次数或等待时间；旧配置 maximum_attempts 仍可读取，但运行时归一为 1。
默认 `quadratic_response` 在预定采集完成后才做拟合和独立验证，保留所有弱响应。
组合激励固定为 Q1-/Q2+ 及其反向，不以初步线性方向筛掉试验。事务、超时与生命周期门控保留。
旧 `legacy_local_linear` 仅用于兼容显式 API 调用，仍保留旧辨识条件。
最终验证未通过状态为 validation_failed。再次试验必须由用户手动启动。

成功保存后前端选入正式标定，操作员重新初始化并通过原设备门控后启动 PID。
成功结果始终导出 MPC 建模数据包，保留原始曲线及训练/验证分组；当前 MPC 拟合
未通过不阻止已通过验证的 PI 应用，也不宣称 MPC 已具备部署条件。
