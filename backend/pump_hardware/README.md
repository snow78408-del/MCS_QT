# backend/pump_hardware

本目录用于泵硬件交互部分。

## 职责

- 硬件连接
- 初始化
- 流速下发
- 状态读取
- 停机

## 逻辑泵定义

- 新 `Q1` = 原注射器1
- 新 `Q2` = 原注射器2
- 原注射器3不参与系统运行

## 扩展要求

- 该部分应支持替换不同硬件协议与不同泵适配器。

`FlowUpdateResult.command_id` 由编排层为每次运行中调流尝试分配，用于关联提议、回读、失败及取消日志；通信层默认值为 0。该编号不代表泵实际完成了物理流量响应。

当前泵的 WSP 参数在运行中回读成功并不代表新流量已生效。`update_flow_while_running()`
现在先核验停泵，再核对两通道参数；已在停泵状态回读确认完全不变的通道
可省略重复写入，变化的通道仍须写入并回读。最后重新启动并核验 CH1/CH2 均在运行；
整个事务成功才返回 `ok=True`。任一步失败后执行安全停泵，并在可能时回滚已写入的
参数，保持停机。调用方以重启完成的时刻作为新流量阶段起点，不能以参数回读时间
或旧的连续运行状态作为生效证据。

## 本次实机通信证据

2026-09-07 本机设备在 1200/8/E/1、地址 1 下成功回读 RSS、RSE、RSP1、RSP2；N 校验的 RSE 查询超时。回读时泵已停止，CH1/CH2 参数换算值约 69.93/20.00 μL/min，并非实测流量。查询耗时不能作为物理响应延迟。该结果只适用于本次设备，不修改通用默认配置；详见 [实机验证记录](../../docs/live_hardware_validation_20260907.md)。
