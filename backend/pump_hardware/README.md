# backend/pump_hardware

本目录用于泵硬件交互部分。

## 职责

- 硬件连接
- 初始化
- 流速下发
- 状态读取
- 停机

## 逻辑泵定义

- 新 `Q1` = 原注射器1
- 新 `Q2` = 原注射器2
- 原注射器3不参与系统运行

## 扩展要求

- 该部分应支持替换不同硬件协议与不同泵适配器。

## 当前 TS 注射泵协议

- 上位机串口固定按 `1200/8/E/1` 使用，默认不自动降级为无校验。
- 帧为 `E9 + addr + len + pdu + fcs`，`E8`/`E9` 在帧体中分别转义为 `E8 00`/`E8 01`，`fcs` 是 `addr` `len` `pdu` 的逐字节异或。
- WSS/RSS 在使能位和拷贝位之后，按通道交错排列 `延时值(2) + 延时单位(1)`，共四组。
- `enable_mask` 是通道使能位；`copy_mask` 是运行时参数拷贝源，最多选中一个通道。Q1/Q2 独立控制时 `copy_mask=0`。
- WSP 直接写入通道参数，用 RSP 逐字段回读校验；不使用 WSS 的 `copy_mask` 作为“参数提交”命令。
- 所有写入值在组帧前按规约范围检查，越界值不会通过字节截断静默下发。

`FlowUpdateResult.command_id` 由编排层为每次运行中调流尝试分配，用于关联提议、回读、失败及取消日志；通信层默认值为 0。该编号不代表泵实际完成了物理流量响应。

当前泵的 WSP 参数在运行中回读成功并不代表新流量已生效。`update_flow_while_running()`
现在先核验停泵，再核对两通道参数；已在停泵状态回读确认完全不变的通道
可省略重复写入，变化的通道仍须写入并回读。最后重新启动并核验 CH1/CH2 均在运行；
整个事务成功才返回 `ok=True`。任一步失败后执行安全停泵，并在可能时回滚已写入的
参数，保持停机。调用方以重启完成的时刻作为新流量阶段起点，不能以参数回读时间
或旧的连续运行状态作为生效证据。

## 实机通信证据

2026-09-28 更换后的 TS 注射泵在 1200/8/E/1、地址 1 下成功回读 RSS、RSE 及四路 RSP；回读时系统与四通道均处于停止状态。CH1/CH2 参数换算值为 50/20 μL/min，它们是设备参数换算值，不是外部流量计实测值。实机 RSP/RSE 原始回包已固化为协议回归测试。

2026-09-07 的旧设备通信记录仍保留在 [实机验证记录](../../docs/live_hardware_validation_20260907.md)，不作为当前泵的默认协议依据。
