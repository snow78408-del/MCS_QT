## 1. 模块职责
`vision` 负责图像识别链路：液滴检测、轨迹跟踪、液滴内磁珠统计、统计指标计算和标准化输出。
本模块可独立运行测试，不耦合前端界面、不包含 PID 控制和泵通信。

## 3. 每个文件功能
- `config.py`：统一管理参数（半径范围、圆度阈值、ROI、匹配距离、最大未匹配帧数、磁珠面积、debug 开关、tracker 类型、Kalman 参数等）。
- `camera_profiles.py`：按相机厂商/型号提供可编辑的推荐起始参数，并负责下发前的类型和范围预校验。
- `cameras/`：工业相机统一接口、设备注册表和生命周期管理；当前优先使用海康机器人适配器，其他厂商通过同一适配器接口扩展。
- `flow_locking.py`：**不使用保存的 ROI** 的通道锁定与流速测量。先从时域活动图找出真正在动的连续条带（静态管壁、灰尘、台面纹理不会出现在活动图里），排除左侧混沌腔体，再在剖面的**动态分量**上做平均相位相关测速；相关谱加下限正则以避免强周期液滴串退化为零位移，并按液滴间距展开、跨 frame gap 取一致解，必要时用已知流向把无歧义量程从一个间距扩展到整间距。输出 `FLOWING / STATIC / NO_SIGNAL / AMBIGUOUS / DISAGREE` 等判定、混叠余量、窗内残差与液滴频率。可离线运行：`python -m backend.vision.flow_locking --video stack.npy --rate 320`。测量链有两条采样路径：`channel_profiles()` 在固定行带上平均，`duct_centre_line()` + `centreline_profiles()` 则先在时域 90/10 百分位差图上逐列跟踪管道的中心线（该图上静态管壁与照明梯度会互相抵消），再沿这条线采样。实机上管道在传感器上是斜的（`row = 0.063x + 241`），固定行带会把剖面对比度从 7.6 压到 2.3 灰度级，足以让任何阈值法的长度估计失真；`measure_flow()` 因此会同时算两条剖面，取对比度更高且仍能测到周期信号的那条，并在结果里用 `profile_source` 标注（`"band"` / `"centreline"`）。回归测试见 `tests/test_flow_locking.py`（21 项）。

  **静态管壁测量（2026-09-19 新增）**：`duct_walls()` 在时域平均图上先逐行减去行均值（照明斜坡约 10 灰度级，比管壁对比度还大），再全局搜索倾角把两条管壁剪切成水平、取行剖面中间距 ≥ `min_gap` 的两个最强局部极大得到名义间距，最后逐列在 ±4 px 内亚像素细化，按 3×MAD 剔除离群列；管壁对比度低于 `min_contrast`（默认 1.0 灰度级）时拒绝，避免把噪声拟合成通道。这是图像里**唯一既静态又锐利**的长度，标尺只能挂在它上面——挂在液滴串上是循环论证，因为滴长本身是流量的函数。2026-09-18 长录实测 **27.011 ± 0.320 px**（497/542 列，倾角 +0.0665），参考录像 **26.931 ± 0.250 px**，即同一根管道、同一套光学。注意：`duct_centre_line()` 追的是**动态信号最强**的一条线，它稳定地落在管道中线**下方约 +14 px**（贴近下壁），那不是几何中心，但那里信号最强（自相关 0.645 vs 管道中线的 0.454）——测速用它、量几何用 `duct_walls()`，两者用途不同不可互换。

  **多 gap 残差容差已收紧**：由 `max(0.10·pitch, 2.5)` 改为 `max(0.03·pitch, 1.5)`。10% 间距的容差无法区分相邻两个间距周期：长录整段窗口里 gap 残差 18.01 px（间距的 10.4%）曾被「三取二」放行。收紧后参考录像仍给出 −47.98 px/帧（真值 −47.6，误差 0.8%）。另：曾加入「灰度调制 < 1.5 判 LOW_CONTRAST」的闸门，**已撤销**——长录的中心线剖面有 9.76 灰度级，与参考录像的 9.77 相同，闸门会误杀好数据；长录三个窗口相差 26% 的原因是**真实加速**（见 `docs/plant_model_wall_geometry_20260919.md` §3），不是噪声。`measure_flow()` 现在报告 `image_range` / `moving_rms` / `moving_pp` / `duct` 作为诊断量，但不据此下判定。
- `channel_region.py`：液滴识别前的启动检定；先将每帧空间梯度转换为局部高频能量，以统一量纲融合 12 帧并过滤未达到最低持续帧比例的瞬时信号，由“管内高频、管外低频”的明显区域界线产生边界候选，再把两侧界线拟合、验证为近似平行的直线管壁，最后透视摆正有效区域。原始图像中的强直线不再直接参与候选生成。采样期间不产生液滴/PID 有效结果；该步骤可关闭，可信度不足时自动回退整帧识别。
- `plug_geometry.py`：塞状液滴的**等效球直径口径单一来源**。检测器报给 PID/MPC/标定记录的
  "直径"不是任何真实液滴的直径，而是与柱塞同体积的球的直径：
  `A_eff = h*w - (4-pi)/(2/h+2/w)^2`（方管 = `0.94635*w^2`）、`V = correction*A_eff*(L - w/3)`、
  `d_eq = cbrt(6V/pi)`。模块同时提供反解（把目标直径换回柱塞长度，便于用卡尺核对）、
  `PlugGeometry`（像素域与微米域一次给全）和 `sphere_diameter_um()`。`detector._plug_equivalent_diameter_px`
  已改为调用本模块，测试锁死两者一致，避免出现第二个口径来源。
- `detector.py`：正式运行采用生成区塞状液滴识别：摆正管道后对中心带建立一维强度剖面，配对前后弯月面得到长度，并用用户填写的 H×W 通道体积公式换算等效球径。观察区 Hough 圆检测仅作为旧调参文件兼容模式保留。
- `tracker.py`：统一跟踪接口和数据结构（`DropletTrack`、`TrackingResult`、`BaseTracker`）。
- `nearest_tracker.py`：最近邻跟踪实现，保留基础行为用于快速基线验证。
- `kalman_tracker.py`：Kalman 跟踪实现（`x,y,vx,vy`），支持预测-匹配-更新和短时丢检维持。
- `bead_counter.py`：液滴内磁珠/小黑点识别与统计，统一 intensity 与 connected 两种模式。
- `metrics.py`：统计指标计算，区分控制输出与分析输出。
- `pipeline.py`：主流程编排，串联 detector/tracker/bead_counter/metrics，输出统一 `VisionResult`。
- `run_vision.py`：vision 独立运行入口（本地视频、摄像头、可视化、统计输出）。
- `preprocess/rotate_video.py`：视频预处理工具，提供旋转能力并可命令行使用。
- `legacy/`：旧脚本归档目录，仅作历史参考。

## 4. channel_region / detector / tracker / bead_counter / metrics / pipeline 关系
- `channel_region`：启动时从原始大图确定两条直线管壁围成的有效区域；手动 ROI/管壁优先，自动失败则回退整帧。
- `detector`：从生成区有效管道得到液滴中心、塞长和等效直径。
- `tracker`：将跨帧检测结果关联成稳定轨迹 ID。
- `bead_counter`：基于活动液滴轨迹统计每个液滴的磁珠数量。
- `metrics`：基于轨迹与磁珠统计生成控制和分析指标。
- `pipeline`：统一调度上述模块并产出标准化 `VisionResult`。

## 5. nearest 与 kalman 跟踪器区别
- `nearest`：实现简单、调参直观；在短时漏检/运动扰动下更容易出现 ID 跳变。
- `kalman`：引入运动状态预测（`x,y,vx,vy`），短时丢检时可依赖预测维持轨迹，稳定性更高。

## 6. 默认版本与切换方式
- 默认：`kalman`。
- 切换方式：运行时通过 `--tracker nearest|kalman` 切换。

## 7. preprocess 子模块职责
`preprocess/` 专门放置识别前预处理工具（旋转、裁剪、分辨率、方向标准化等），与检测/跟踪/统计主链路解耦。

## 8. rotate_video.py 作用
- 将输入视频按指定模式旋转后输出（`ccw90` / `cw90` / `180` / `auto` 占位）。
- 可作为可复用函数被 `run_vision.py` 调用，也可独立命令行运行。

## 9. 独立运行 vision 模块
示例：
- 本地视频：`python run.py vision --video input.mp4`
- 摄像头：`python run.py vision --camera 0`
- 跳过自动管道检定：`python run.py vision --video input.mp4 --skip-channel-region`
- 启用 Kalman：`python run.py vision --video input.mp4 --tracker kalman`
- 运行前预处理旋转：`python run.py vision --video input.mp4 --preprocess-rotate ccw90`

## 10. 独立液滴识别调参工作台

现在可以从主软件左侧导航进入“7 液滴算法调参”，完整调参工作台会直接嵌入主页面，不进入控制流程。也可以在不启动主软件时直接运行：

```bash
python run.py tune --video path/to/sample.mp4
```

调参工作台和正式实时管线现在都强制使用 `generation_plug`，不会因旧参数退回观察区圆检测。生成区可调图像参数为中心带比例、弯月面 MAD 阈值、最小峰距、塞长/管宽范围、相内外对比、二维弯月面支撑、上下胶囊边缘覆盖率和亮暗极性。候选必须同时具有左右弯月面与持续的上下轮廓，只有左右界面的连续相间隙不能登记为液滴；亮暗极性仅用于评分，以兼容相差光晕造成的局部极性反转。用户填写的 H×W 通道尺寸、像素比例与体积修正系数属于物理标定，由相机/ROI 配置维护，保存图像阈值时不会覆盖。

当前帧先用四个大卡片展示“管道区域检定”：原始大图、局部高频区域、高低频界线拟合和最终有效区域/可信度；之后展示生成区原图、灰度/光照校正、中心采样带、轴向强度/边缘峰、弯月面配对和等效直径。页面明确显示当前 `μm/px`，预览长度门限和直径换算与实时识别一致。保存文件采用分组 JSON，包含 `channel_region` 与 `detector` 两组参数。

跟踪器仍默认采用 3 帧窗口至少 2 次命中才确认轨迹，确认后短时漏检由 Kalman 预测维持。工作台不会连接相机、泵机，不运行跟踪、磁珠识别或 PID。

仅在正负相位均有足够证据时使用该分段，否则沿用原轮廓包络。相位分段允许

## 12. 当前版本优点
- 从大脚本拆分为模块化架构，职责边界清晰。
- 提供最近邻与 Kalman 双跟踪器，可按配置切换。
- 输出数据结构标准化（`VisionResult`、`DropletTrack`、`TrackingResult`、`BeadResult`）。
- 预处理与识别主流程解耦，便于后续扩展。
- 预览帧与识别结果分别维护帧号和时间戳，PID 只使用同一次识别产生的数据。
- 实时统计按轨迹 ID 去重，避免同一液滴停留多帧时被重复计入控制样本。
- 检测尺寸由图像域半径范围或显式图像标定约束，不受 PID 目标直径影响。
- 相机测试和正式运行使用同一套参数下发路径；支持的参数写入失败时会终止测试，不静默继续。

## 13. 相机适配边界
- `cameras/base.py` 定义厂商无关接口，`registry.py` 负责后端注册和优先级。
- 海康机器人是当前启用和优先后端，保留现有 MVS/直接 SDK 兼容路径。
- 新相机只需新增适配器并注册，不应把厂商 SDK 调用写入 detector、pipeline、orchestrator 或前端。
- 海康直接 DLL 路径可确认写入调用是否成功；曝光、增益和帧率的精确回读能力取决于当前 SDK 路径，分辨率会通过实际测试帧再次校验。

## 14. 待改进方向
- 引入 Hungarian/IoU 等更稳健匹配策略。
- 管道区域检定阈值的更多真实相机样本自适应。

## 15. 连续过线计数与尺寸批次（初版）

启用 PID 帧批次控制后，尺寸处理使用操作员设置的 N/M 帧数；连续过线计数仍独立观察每个接收帧。`MetricsCalculator.begin_frame_batch(M)` 按分析帧数结束统计窗口：最后一帧计入本批，不等待下一个时间窗或重复处理最后一帧。每个过线液滴仍只贡献一份尺寸；新批清除已有轨迹的历史尺寸样本，保留跟踪身份及去重计数，避免混入调流前尺寸或重复计滴。非 PID 批次模式继续沿用下述时间窗口行为。

`PipelineVisionService` 保留原有采集、采样、尺寸处理、预览工作线程，不新增泵线程。
采样线程先运行 `ContinuousLineCounter`，再决定是否组织连续五帧尺寸批次。
GUI 与计数不会直接发送泵命令；编排层继续按原控制周期、数据有效性和同周期去重规则调度。

- 本版要求人工选定两条管壁；几何不变时缓存透视采样坐标，每帧仅在尺寸统计计数线位置采样 5 列、最多 64 行，不重复自动寻找管壁。计数事件为尾端离开，尺寸跟踪事件为中心越线，两种事件存在相位差，不能按单滴时间戳直接等同。
- 前 32 帧估计高低对比阈值，随后用双阈值状态机记录完整通过事件。尚未完成校准、缺帧、时间倒退、历史覆盖不足时，频率无效；前端显示 `--`，不是 0 Hz。
- 采用采集端单调时钟（可用时）与硬件帧号（可用时）；没有硬件帧号时只能检查应用层帧连续性。
- 尺寸统计输出完成窗口的起止时间，计数查询同一个半开窗口 `[start, end)`，频率为事件数/窗口时长。窗口未结束不发布新的控制周期；分析跨过多个周期时不把旧尺寸重新标成新数据。
- 队列和计数历史都有上限；尺寸分支可跳过批次，频率分支缺帧则明确拒绝该窗口。频率目前只用于监测，不作为 PID 的输入，也不代表尺寸分支测到了所有液滴。
- 单线计数适用于稳定单向、液滴与间隙均能被帧率解析的流动。反流、合并、断裂及照明漂移尚未验证，不能将过线频率无条件等同于生成频率。阈值在重新开始或 ROI 变更时重新校准。
- 尺寸检测增加横向轮廓包络来区分液滴与间隙；中心弯月面峰弱时可由包络提供端点候选，仍需满足长度及上下轮廓覆盖约束。等效球径仍依赖真实 H、W、像素比例及体积模型标定，不等同于直接实测球径。

无硬件回放（两条管壁按归一化坐标传入；换成实际视频与实际管壁）：

```powershell
.venv\Scripts\python.exe tools\replay_continuous_counter.py sample.avi --walls 0 0.2 1 0.2 0 0.8 1 0.8 --period 10
.venv\Scripts\python.exe -m pytest
```

输出逐事件帧号、完整窗口的频率有效性、轻量计数耗时。视频不足一个控制周期时不生成完整窗口；需要独立逐事件标注才能评估漏计和重复计数率。

## 16. 尺寸质量与计数口径

- 尺寸有效性来自检测器的完整性/轮廓检查、有限正尺寸和物理标定，不按目标误差或群体 MAD 删除大液滴。每条过线轨迹锁定有限测量历史的中位数，每个液滴在周期统计中只占一份；CV 高本身不使尺寸无效。
- 没有可靠比例的微米尺寸只供预览，不计为有效物理尺寸样本，也不授权反馈；没有尺寸时均值、标准差和 CV 为 None。
- 快照新增 `current_frame_droplet_count`（当前确认轨迹）、`window_passage_count`（尺寸跟踪窗口通过数）、`valid_size_sample_count`（标定有效的窗口尺寸样本数）。`total_droplet_count` 仍为尺寸跟踪累计通过数；`frequency_passage_count` 是独立连续计数链路的窗口通过数，只有 `frequency_valid` 为真时有效。二者事件定义不同，不互相替代。
- `measurement_quality_valid/reason` 描述尺寸计量质量；`valid_for_control` 加上编排层时间门控才决定能否驱动当前反馈。有效尺寸可以保留展示但因时间归属不合格而不参与调泵。
- 测量样本起止时间与尺寸中位数实际保留的帧一致；采集顺序异常在更新跟踪和计数前拒绝，不把旧帧加入新窗口。

## 17. 原图背景纹理抑制

生成区候选现在同时通过增强图几何条件与原图轮廓对比检查。原图仅做轻度平滑，取候选主体和左右连续相的横向中位数剖面，分别相减后计算 5–95% 幅值范围，取两侧较小值。固定管壁和横向一致的亮度阶跃会被抵消；单侧边界、缺少背景参照或只在增强图上明显的纹理不会作为完整尺寸。

`DetectorConfig.generation_min_raw_outline_contrast` 默认 12 个原始 8 位灰度级，调参工作台可修改，取值 `(0,255]`。这是经过本次样本复核的图像质量门限，不是适用于所有曝光条件的物理常数；更弱的真实轮廓可能被拒绝，降低门限时应同时复核无液滴背景样本。检测器不使用目标直径或泵状态做此判定。旧 schema-v1 参数文件只在内存补全该字段，其他配置及原文件保持不变。

独立连续计数使用 `ContinuousLineCounter.minimum_phase_contrast=12` 约束启动窗口内两相对比变化，防止把低幅纹理闪烁自行校准为两相。该信号不同于尺寸轮廓差，不与尺寸门限自动联动。启动窗口仍为 32 帧，未增加控制等待或采样延迟；质量不足时频率为无效，不输出可信的 0 Hz。

验证记录见 `docs/background_texture_validation_20260907.md`。

## 19. 密集液滴的背景参照

生成区原图轮廓检查的左右背景窗口现在限制在相邻包络之间，避免把邻滴当作连续相而使两滴同时漏检。边缘残滴和长度不合格的候选也参与背景边界限制。每侧仍至少需要两列背景像素，仍执行原始对比度门限和轮廓检查；没有可分辨间隙时不借用邻滴像素。此调整不改变包络分割、尺寸模型、连续计数或硬件参数。

## 20. 扶正几何与测量入口单一来源（2026-09-24）

`plug_geometry.rectified_axes(shape)` 是扶正图**轴向、横向、像素个数、索引跨度**的唯一定义。轴向由**扶正变换契约定死**，不是推断：`rectify_channel_frame` 的目标四边形是 `[[0,0],[W-1,0],[W-1,H-1],[0,H-1]]`，管壁方向映到 **x**、跨管方向映到 **y**，因此 `flow_axis` 恒为 `"x"`——**与图像哪一边更长无关**（早先按长边推断会把 80×40 的扶正图静默转轴成沿 y 流动）。三个量必须分开：`*_pixel_count` 是该轴上的像素个数，`*_index_span` 是索引跨度（= 个数 − 1，实测长度是索引差，**门槛与检测参考宽用这个**），而**几何长度**由 `rectified_roi.wall_separation_px` 给出（透视输出高度的像素距离），与索引跨度相差端点归一化，两者不可混用。调用方必须用本函数取值，**不得再用 `min(gray.shape)` 猜**。传整幅三维 shape 会被拒绝。

`detector.detect(frame, mode=None, *, channel_width_px=None, flow_axis=None, trace=None)` 把**本帧**横向索引跨度与显式轴向传入检测：它们是长度门槛与边缘间隔门槛的参考（trace 里的 `reference_width_source` 会注明来自 `frame_rectified_geometry` 还是 `config_nominal_geometry`，`flow_axis_source` 注明 `explicit` 还是 `longer_side_heuristic`）。**扶正图必须显式给轴向**。`backend/vision/rectified_measurement.detect_rectified_generation_plugs()` 是扶正图检测的唯一入口，`measure_generation_plugs()` 是测量的唯一入口，**生产路径（含实时 `VisionPipeline`）与诊断工具都必须经它们**。`PipelineConfig` 的实时管线在 `detection_geometry` 里记录本次实际使用的参考几何与来源，便于同帧一致性核对。名义 50 µm 与默认倍率不得当作本帧像素宽度。

`detector.declare_pixel_cross_section(cross_px, *, reason)` 用于纯像素域诊断：它把名义通道显式声明为本帧观测截面，使门槛与画面自洽，隐含 1 px = 1 µm，**不产生任何 µm 结论**——物理单位仍由 `ScaleEvidence` 与芯片深度闸门挡住。注意它取的是**像素个数**（要与 `wall_separation_px` 自洽），不是索引跨度。声明内容进入 trace 以便审计。

几何不一致（`detector_duct_geometry_mismatch`）仍然作废整条测量（`valid=False`），但检测已跑完，**像素域候选会保留**：诊断需要看到候选与门槛，只是不得用于控制或物理标定。

**帧身份**：`FrameEvidence` 的软件序号与硬件帧号来自**不同计数器**，实测软件序号 0 对应硬件帧号 74、录像末尾相差 317，因此**不要求二者相等**；硬件帧号必须存在且为正，缺失即按证据不足拒测——不许把一个字段填成另一个字段的值来通过检查。
